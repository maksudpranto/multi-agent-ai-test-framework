The user's requirement: the generated test cases and every feature must be **genuinely AI-powered**, not the deterministic mock. The app was already provider-agnostic (`LLM_PROVIDER` mock/gemini/anthropic/ollama) but defaulted to `mock`. Switching is now a config change, not code.

**What powers it now:** `LLM_PROVIDER=gemini`, model **`gemini-flash-latest`** (an alias → resolves to a current thinking Flash model, e.g. gemini-3.6-flash). The user's free key had `limit: 0` on `gemini-2.0-flash` and `gemini-1.5-flash`/`2.5-flash` return 404 for new users — `gemini-flash-latest` is the durable free choice. Verified end-to-end: real, banking-domain-specific requirement analysis + 20 varied test cases (functional/boundary/api/security/negative) vs the mock's 3 canned templates.

**Key wiring (all committed):**
- `config.py` — `_PROVIDER_DEFAULT_MODEL` + `Settings.effective_model`: a mock/blank `DEFAULT_LLM_MODEL` while a real provider is selected auto-resolves to the provider's default, so "make it AI" = provider + key only. A real user-set model is respected.
- **Thinking-model gotcha:** Gemini 2.5/3.x flash spend part of the output-token budget on internal reasoning (`thoughtsTokenCount`); a small `max_tokens` returns empty `content` with `finishReason=MAX_TOKENS`. Fixes: `gemini_provider.py` parses defensively (no more KeyError on missing `parts`; raises a clear ValueError on MAX_TOKENS / safety block) and `RunConfig.max_tokens` bumped 4096→8192.
- **Visible indicator:** `GET /meta/llm` (provider/model/is_mock/ready/key_missing) + a sidebar badge in `AppShell.jsx` (green "Google Gemini · gemini-flash-latest" when ready, amber if mock or key missing). CSS `.llm-badge`.
- Tests isolated from deployment `.env` via `Settings(_env_file=None, …)`; 16/16 pass. `mock` stays the default in code for offline tests/dev.

Cost note: real runs are no longer free/instant — each pipeline stage is one Gemini call (a few seconds), counts against the free-tier quota, and quota exhaustion returns HTTP 429. See [[agentic-orchestrator]].

**Multi-model + per-run UI picker (later increment):** the app now offers several FREE models the user picks per run from a dropdown in the RequirementDetail header — no file edits. Backends: Gemini (2 models), **Groq** (llama-3.3-70b / llama-3.1-8b, OpenAI-compatible, ~sub-second) and **OpenRouter** (DeepSeek R1, Llama, Qwen `:free`). Key design: ONE `app/llm/openai_compatible.py` provider class serves every OpenAI-compatible host (Groq/OpenRouter/Cerebras/Together) — new free hosts = a base_url, not a new class. `app/llm/catalog.py` = the free-model list (single source of truth); `GET /meta/models` returns it with a per-model `ready` flag (key present). Selection: the client (`getModelSelection`/`setModelSelection`, localStorage key `matf_model`) attaches `{provider,model}` to every pipeline POST; each route calls `_resolve_run(selection)` → validates vs catalog, 400 if the provider's key is missing, builds `DefaultWorkflowEngine(service_for_provider(provider))` with `config.model` set. `service_for_provider` is lru_cached per provider. All three providers verified end-to-end (the chosen model shows up in `AgentExecution.model`). This per-run switching is what enables the thesis ablation (same requirement across models). Keys: GROQ_API_KEY, OPENROUTER_API_KEY in backend/.env.

**Usage/quota panel + 413 fix:** `GET /meta/usage?session_since=<iso>` (`app/llm/usage.py`) counts LLM calls from `AgentExecution` rows (model→provider via `catalog.provider_for_model`), bucketed today/month/session per each provider's reset tz (Gemini=PT, Groq/OpenRouter=UTC), plus approximate free daily caps + next reset. `UsagePanel.jsx` renders per-provider bars (today/limit, remaining, session/today/month, "resets in Xh"); shown on Dashboard + RequirementDetail overview. It refreshes on a 15s poll, on window focus, and instantly via a `matf:usage` window event the api client fires after every pipeline call (`pipe()` wrapper). "This session" = sessionStorage `matf_session_start`. Also fixed the planner row to record `config.model` so orchestrator planner calls are counted. IMPORTANT gotcha: Groq's free 8B tier rejects `max_tokens=8192` with **HTTP 413** (per-minute token cap) — `openai_compatible.py` now halve-and-retries on 413 down to a 2048 floor, so capable models keep 8192 and constrained ones self-heal. Caveat surfaced in UI: counts only calls made through this app; free tiers are daily (no monthly cap) so "month" is usage-to-date. All verified live in-browser (Groq run bumped session 0→1, remaining 999→998).

**Live provider-reported quota (authoritative fix):** app-log counts diverge from a provider's own dashboard because (a) diagnostic/out-of-app calls aren't logged and (b) each 413 retry is 2 real calls but 1 logged row. Fix: `app/llm/ratelimit.py` caches the `x-ratelimit-*` headers each OpenAI-compatible response returns; `openai_compatible.py` records them + learns a per-model token ceiling (`_MODEL_TOKEN_CEILING`) so it stops burning a request on the guaranteed-413 first attempt. `usage.py` prefers this live value (`source:"provider"`) over the estimate. **Groq truth (this account): 14,400 requests/DAY but only ~6,000 tokens/MINUTE — TPM is the real cap, which is why max_tokens=8192 → 413.** Gemini: no live quota API (stays estimate). OpenRouter: returns no rate-limit headers → estimate. NOTE (Aug 2026): OpenRouter's `:free` catalog churned entirely — DeepSeek/Llama/Qwen `:free` are gone; current verified free ids are `nvidia/nemotron-3-ultra-550b-a55b:free`, `openai/gpt-oss-20b:free`, `nvidia/nemotron-nano-9b-v2:free` (fetch `GET /api/v1/models` and filter `:free` when they break again). UI tags each provider `LIVE` (green) or `EST.` (grey) with a footer explainer. ratelimit `_STATE` is per-process (only populates after the SERVER makes a call, not standalone scripts).
